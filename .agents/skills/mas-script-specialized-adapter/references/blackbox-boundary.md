# 黑箱边界：专项适配红线

适用范围：所有专项适配（`app/task/*`）的需求评估、方案设计与代码审查。本文件规定判据与提示要求，不构成开工许可。

## 推进顺序：先降门槛，再补缺位

1. **先降低配置门槛**：消除安装导入、路径选择、首次配置与高频任务编排中的手工步骤，减少用户需要调整的选项。
2. **再补本体缺位**：仅当第 1 步无剩余空间、且缺口确属 MAS 领域时，才实现补位。

立项判定（新功能必须先回答）：

- 它消除了用户当前必须手工完成的哪一步？答不出具体步骤，不立项。
- 若以「补齐上游缺位」立论：缺位是否属 MAS 领域？上游是否确实没有任何等效入口？两者同时成立才立项。

反模式：

- 配置门槛没有下降，却在上游已有能力之上自建功能；
- 把上游原始配置面板原样搬进 MAS，并当作门槛降低；
- 补出的功能没有对应用户场景与手工步骤，只是「字段齐全」。

## 判定：能力归属

先判定能力属于谁，再决定 MAS 能否实现。

1. 这件事是不是「脚本该干的活」？涉及**游戏内操作**（登录、切号、进本、战斗）、**脚本任务的执行与成败判定**、或**脚本配置语义**，即为上游领域。
2. 操作对象是**游戏本体**，还是上游程序或模拟器？直接操作游戏本体一律属上游领域；操作上游程序、模拟器或操作系统属复用或 MAS 领域。

| 归属 | 范围 | MAS 可做 | MAS 不可做 |
| --- | --- | --- | --- |
| 上游领域 | 游戏内操作、脚本任务的执行与成败、脚本配置语义 | 复用其入口；用其既有机制驱动 | 自行实现这些能力——**无论上游当下是否已有** |
| MAS 领域 | 用户与账号管理、多脚本/多实例调度、计划表、通知、统计与历史、模拟器生命周期、跨脚本编排 | 自行实现，判定权归自己 | 读取或反推上游内部状态 |
| 上游私有格式 | 配置文件内部字段、计划/队列/运行记录、资源文件、源码内部 | 透传读写：值经手、语义不过手 | 在其上建映射表、平行模型或自造判定信号 |

**「补位」只在 MAS 领域成立。** MAS 替上游补出其领域能力（游戏内操作、任务执行与判定）不是补位，而是越界；上游缺失不构成许可。

## 三种合规介入方式

1. **复用**：CLI、原生 GUI 与配置会话、上游文档化接口。
2. **驱动**：用上游既有机制表达 MAS 意图——写配置或队列字段、传启动参数、启进程；执行与成败判定仍归上游。
3. **MAS 领域实现**：MAS 领域能力自行实现，不读取也不反推上游内部状态。

不属于以上三者，即为越界。

## 附加约束

| 轴 | 合规 | 违规 |
| --- | --- | --- |
| 执行权与判定权 | 上游执行的任务，成败取自上游结果面（日志、报告、退出码） | 上游执行的任务，适配层自打标记并自行判定成败 |
| 语义所有权 | 透传：只写入或读取上游字段 | 复制：在上游私有格式之上维护适配层模型、字段映射表或状态机 |
| 失效可发现性 | 上游变更后响亮失败（注入无效、报错、任务不生效） | 上游变更后静默误判（字段被忽略、仍判成功） |

## 允许依赖：上游对外契约

- CLI 参数、`--help` 声明、退出码
- 上游文档化的 JS/API、脚本与插件接口
- 原生 GUI 与配置会话（适配层只负责打开与切回）
- 进程名、发行版目录结构、可执行文件相对路径
- 日志文案与滚动行为、运行报告等用户可见输出

## 禁止复制：不在上游私有布局之上建语义层

- 上游配置文件内部字段之上的字段映射表或平行模型
- 上游计划、队列、任务顺序、运行记录等私有格式的副本
- 上游资源文件、数据库内部结构的再解析结果
- 上游源码类名、方法名、私有异常文案、内部状态机
- 取代上游结果面的自造判定信号（对上游执行的任务自行打标记再自行解析）

## 时效与存量越界

上游领域能力在上游缺失期由 MAS 实现，不因当时上游没有而转为合规，属历史容忍。上游提供同能力入口后，按存量越界处理，优先级高于「收口隔离」：

1. 改为复用上游入口；
2. 移除适配层实现及其配置项、前端入口与判定逻辑；
3. 不保留两套语义并存。

## 例外：解析上游内部字段的条件

同时满足以下四条方可实施：

1. 有核查证据表明上游无 CLI、无文档化接口、无日志或退出码可用的等效路径；
2. 开发者明确接受该耦合；
3. 解析集中在单一模块，并标注上游变更时的失效表现；
4. 不因解析结果扩展平行模型；可从上游入口获取的数据不再解析。

参考案例：[examples-zzzod.md](./examples-zzzod.md)。

## 提示要求

加载 `mas-script-specialized-adapter` 后，任何专项适配任务在需求澄清与方案设计阶段先按上文自检，无需等待提问。命中时输出：

1. 结论：**「这可能违背了 MAS 的开发规范」**；
2. 命中条目：上游领域能力由 MAS 实现、在上游私有布局之上建语义层、存量越界；
3. 证据：`file:line`，或上游已有对应能力的位置；无法确认时标注待核实，不得编造；
4. 替代方案与代价：复用上游入口、改由上游提需求、或收口隔离。

提示不阻断工作，是否继续由开发者决定；继续时在任务结果中记录「已提示规范风险，开发者确认继续」。

以下理由不构成豁免：字段齐全、与上游界面一致、实现成本低、上游暂时没有、先实现再调整。

存量越界处理优先级：改为复用 > 移除 > 收口隔离；同样只提示，由开发者定夺。
