# 案例：BAAH（碧蓝档案爱丽丝助手）

BAAH 是**独立发行版 + 自带 JSON 配置体系**的线：入口 `BAAH.exe <配置名>.json`，配置由它自己的 jsoneditor 界面维护，MAS 不复制配置目录、不做字段化，只以「配置文件名」引用 BAAH 原有配置，并在运行期对少量关键字段做托管。模拟器不归 BAAH 管，由 MAS 调度（见下节）。

具体字段、路径、函数名现场读 `app/task/BAAH/` 与 BAAH 发行版确认。本文件只记推不出来的部分。

## 产品决策（读代码看不出为什么）

- **用户身份 = BAAH 配置文件名，不是 MAS 目录副本**。BAAH 的配置是单个 JSON（`BAAH_CONFIGS/<名称>.json`），含大量 MAS 不该理解的任务字段；该脚本自带 jsoneditor 界面就是它的配置 UI。所以 MAS 用户级配置只存 `Info.ConfigName`，运行前把该 JSON 交给 BAAH 自己读，**不把配置搬进 MAS 表单**（与 MAA/Okww 系的"每用户一份配置树"是不同 owner 判定的结果，不是偷懒）。
- **配置名要过校验再拼路径**：配置名直接参与文件路径拼接，必须先拒绝路径分隔符、`..`、非法字符并按需补 `.json` 后缀，否则用户可以借配置名写到任意路径。
- **托管字段取最小集**：只强制两类——运行结束自动退出、日志落盘。任务是 BAAH 自己的模型，MAS 不接管、不改写、不校验其任务语义；字段超出这个集合就叫越权。
- **模拟器归 MAS**：BAAH 只在配置里读 ADB 地址并连过去，启动/等待/关闭由 MAS 做（详见下节）。不要在 BAAH 侧填模拟器路径。

## 上游契约（实测，读发行版与本仓库代码看不出结论的那些）

- **启动**：`BAAH.exe <配置名>.json`，参数必须以 `.json` 结尾；配置名不带后缀时由 MAS 补齐。
- **日志**：写到 `DATA/LOGS/log_YYYY-MM-DD-HH-MM-SS.txt`（文件名即启动时刻）。同一目录里还会出现 `custom_log_*.txt`，**不是**本次运行日志——按前缀匹配日志文件时不要把它们卷进来。
- **日志行格式**：`{版本} - {分:秒} - {级别} : {消息}`，例：`2.4.13 - 24:19 - INFO : 执行任务EnterGame`。
- **成败判据**：成功文本 `所有任务结束`（英文 `All tasks are finished`）只出现在成功路径；失败文本 `运行出错:` / `Error occurred:` 来自顶层异常处理。
- **退出码无约定**：不要拿进程退出码判结果。
- **没有心跳**：只能靠日志推进与进程存活判活。
- **模拟器侧没有"已在运行则跳过"的判断**：对已启动的安卓模拟器再发一次启动，会打印「模拟器启动进程已结束，可能是启动失败，或者是模拟器已经在运行」这种误导性 WARN，而不是安全空转。因此不允许两侧都尝试启动模拟器。

## 托管配置

运行前写入、运行后恢复，快照 + 原子写 + 自校验：

- 托管项：`CLOSE_BAAH_FINISH`（跑完自动退出，否则进程停在 `input()` 永不结束）、`SAVE_LOG_TO_FILE`（开日志落盘）、`TARGET_EMULATOR_PATH` 置空（禁止 BAAH 自己启动模拟器）、`ADB_DIRECT_USE_SERIAL_NUMBER` 关闭。
- **运行期值覆盖静态托管值**：ADB 地址由模拟器调度解析出来（形如 `127.0.0.1:16448`），拆成 `TARGET_IP_PATH` / `TARGET_PORT` 注入——用户因此不需要在 BAAH 里手填端口。
- **写盘必须无 BOM**：带 BOM 的 JSON 会让 BAAH 静默按默认值运行，不报错。
- **恢复要能在"什么都没写"时安全返回**：任务在托管前被用户中止时，收尾阶段拿到的是 `None` 快照，恢复函数必须直接返回而不是访问属性（曾经在此抛 `AttributeError`，线上复现过）。

## 模拟器调度

- 字段挂在专项配置的 `Emulator` 段（`Id` / `Index` / `CloseOnFinish`），并注册进 `related_config` 让前端能取到模拟器下拉。
- 每次尝试前调模拟器的 `open(Index)` 并等设备在线，任务结束按开关 `close(Index)`。**模拟器管理器的 open 是幂等的**——已在线立即返回，所以"让实例常驻"没有收益，不要用常驻去绕冷启动。
- 收尾路径全程幂等：失败重试、手动中止、异常退出都要走到关闭逻辑。

## 陷阱

- ★**日志时间戳切片是字符切片，不是分词字段下标**。`LogMonitor` 的第一个参数作用于**整行**（`line[start:end]`）；BAAH 行前缀是「6 字符版本号 + `' - '`」，时间戳落在 `[9, 14)`，格式 `%M:%S`。写成"第 3 个字段"这类下标会切出单个字符，`strptime` 失败后被 `suppress` 吞掉 → **整轮日志一行都不入库**：界面停在「正在等待 BAAH 日志文件生成」，且成功文本永远匹配不到，任务只能等到超时。（BAAH 适配实测踩过；排障时先看后端日志有没有「成功定位到日志文件」——有就说明文件找到了，问题在采集不在查找。）
- **上游自带的等待窗口短于冷启动**。实测 MuMu 冷启动约 49.7s，而 BAAH 自己的 `check_adb_connect` 重试上限约 45s，于是它先自判失败。把等待移到 MAS 侧（模拟器管理器的在线轮询）之后这个问题消失——这是"模拟器归 MAS"的实际动机，不只是架构偏好。
- **MuMu 的 `-v N` 是实例序号，不是 ADB 端口**。传错序号会让 BAAH 连到别的实例（实测把实例 2 的目标连到了实例 1 的 16416），而日志只表现为"打开游戏失败"。端口规律：`16384 + (index + 1) * 32`。
- 配置名不校验就拼路径 → 目录穿越。
- 托管写入带 BOM → BAAH 静默按默认值运行。
- 收尾恢复不接受 `None` 快照 → 中途停止任务时报 `AttributeError`。

## 审查清单

- [ ] 用户级配置只引用 BAAH 配置名，未把 BAAH 的配置字段搬进 MAS 表单
- [ ] 配置名经过校验后才参与路径拼接，后缀补齐语义明确
- [ ] 托管项仅限「自动退出 + 日志落盘 + 屏蔽 BAAH 自启模拟器」，未越权改任务语义
- [ ] 托管写入无 BOM；快照覆盖"文件原本不存在"的情况；恢复可安全接受 `None`
- [ ] 日志文件按前缀 + 启动时刻定位，未把 `custom_log_*` 当成运行日志
- [ ] `LogMonitor` 的时间戳区间经过真实日志行验算（字符切片，不是字段下标）
- [ ] 模拟器由 MAS 启动/等待/关闭，脚本侧模拟器路径已置空；关闭受用户开关控制
- [ ] ADB 地址由调度结果注入，用户无需手填端口
- [ ] 成功/失败判据取自上游源码文本，未依赖退出码或进程存活
