# 多行聚合指南

> 如果你的需求可以通过字符串切割和表达式实现，我们不推荐使用多行聚合代替，因为窗口的资源消耗和稳定性都不如单行处理。

普通模式（字符串切割、正则）都是**一行一行**处理日志的：一行命中就提取一行。但很多任务的过程信息**分散在多行**里，例如 BetterGI 一条龙任务：

```
一条龙任务执行: 1/4        ← 任务开始
邮件："全部领取"            ← 过程信息
地图特征点加载完成！         ← 噪声，不关心
→ "任务结束"               ← 任务结束
```

如果你想把这些跨行的关键信息**拼成一条推送**，单行模式做不到，这时就用「多行聚合」。

它的工作方式是：

1. 用**起始正则**圈定一段日志的开头
2. 用**结束正则**圈定这段日志的结尾
3. 中间所有行（含首尾）装进一个「窗口」
4. 用**提取表达式**从整个窗口里挑出你关心的字段，拼成一条结果

---

## 从一个例子开始

下面是 BetterGI 一条龙任务的日志片段（每条日志占两行：头一行是时间戳，第二行是内容）：

```
[08:12:12.661] [INF] BetterGenshinImpact.ViewModel.Pages.OneDragonFlowViewModel
一条龙任务执行: 1/4
[08:12:12.662] [INF] BetterGenshinImpact.GameTask.TaskRunner
→ "任务启动！"
[08:12:15.513] [INF] BetterGenshinImpact.GameTask.Common.TaskControl
邮件："全部领取"
[08:12:18.425] [INF] BetterGenshinImpact.GameTask.Common.TaskControl
地图特征点加载完成！
[08:12:19.725] [INF] BetterGenshinImpact.GameTask.TaskRunner
→ "任务结束"
```

期望效果：把任务进度和邮件拼成一条推送：

```
一条龙任务执行: 1/4 -> 邮件："全部领取"
任务结束
```

我的配置可以写作：

| 参数       | 值                                                                     |
| ---------- | ---------------------------------------------------------------------- |
| 起始正则   | `一条龙任务执行`                                                       |
| 结束正则   | `任务结束`                                                             |
| 提取表达式 | `$((一条龙任务执行: \d+/\d+))+" -> "+$((邮件：[^\n]+))\|$((任务结束))` |
| 最大跨行数 | `50`                                                                   |

各步处理效果：

| 步骤                          | 处理结果                                                                                               |
| ----------------------------- | ------------------------------------------------------------------------------------------------------ |
| 起始正则命中 `一条龙任务执行` | 窗口打开，从该行开始收集                                                                               |
| 收集中间行                    | `→ "任务启动！"`、`邮件："全部领取"`、`地图特征点加载完成！` 等全部装入窗口                            |
| 结束正则命中 `任务结束`       | 窗口关闭，对窗口内全部文本执行提取表达式                                                               |
| 提取表达式第 1 行             | `一条龙任务执行: 1/4 -> 邮件："全部领取"`（进度 + 字面量 + 邮件，`地图特征点加载完成！` 未命中被过滤） |
| 提取表达式第 2 行             | `任务结束`                                                                                             |

> 注意：`地图特征点加载完成！` 这一行不匹配任何正则片段，所以被自动过滤掉了。

## 四个参数

| 参数       | 作用                                              | 留空含义                                             |
| ---------- | ------------------------------------------------- | ---------------------------------------------------- |
| 起始正则   | 匹配到此正则的行作为窗口开头（含该行）            | **该规则不生效**（必填）                             |
| 结束正则   | 匹配到此正则的行作为窗口结尾（含该行）            | 窗口只在遇到新起始行、达到最大跨行数或日志结束时关闭 |
| 提取表达式 | 从窗口内容中提取字段并拼接（`$()` 语法 + 函数链） | 返回窗口内所有行的原文                               |
| 最大跨行数 | 窗口最多收集多少行，超出则强制关闭                | 默认 50，防止意外吞掉过多行                          |

> 起始正则是必填项，留空时整条规则不会生效，避免误开启后任意行均可开启窗口造成海量推送。

> **各字段该看哪个文档？** 本文档（多行聚合）讲窗口规则与整体示例，其余语法请配合：
>
> - **起始正则 / 结束正则**：正则写法见《正则指南》
> - **提取表达式**：`$()` 语法、`+` / `;` / `""` 与函数链见《表达式指南》
> - **最大跨行数**：本文档说明

## 窗口是如何工作的

多行聚合是一个**有状态**的过程，逐行读入日志：

- **没有窗口时**：遇到匹配「起始正则」的行 → 开启新窗口，该行作为窗口第一行
- **窗口打开时**：继续收集每一行
  - 遇到匹配「结束正则」的行 → 收集该行后**关闭窗口**，产出一条结果
  - 遇到新的「起始正则」行 → **强制关闭**当前窗口并产出结果，再用该行开启新窗口
  - 收集行数达到「最大跨行数」 → **强制关闭**窗口并产出结果
- **日志结束时**：如果还有窗口没关闭 → **强制关闭**并产出结果（避免丢数据）

关键规则：**同一时刻只允许一个窗口打开**。所以一条规则可以匹配日志里的多段任务，每段任务各产出一个结果。

## 提取表达式

窗口关闭后，窗口内所有行用换行符 `\n` 拼成一段文本，**提取表达式**从这段文本中挑出你关心的字段，拼成最终结果。

提取表达式使用 `$()` 语法，支持 `+`（同行拼接）、`;`（换行拼接）、`"文本"`（字面量）和函数链（`.replace()`、`.cut()`、`.cutby()` 等）。

**简要示例**：

```
$((一条龙任务执行: \d+/\d+))+" -> "+$((邮件：[^\n]+));$((任务结束))
```

输出：

```
一条龙任务执行: 1/4 -> 邮件："全部领取"
任务结束
```

> 提取表达式的完整语法、函数列表和更多示例请参考「表达式指南」。
>
> 提取内容需用捕获组 `()` 标记：`$((任务结束))` 提取整段匹配，`$(任务执行: (\S+))` 提取指定部分；
> **无捕获组时返回空串、该行不输出**。
>
> 提取表达式留空时返回窗口原文（所有行拼接）。
> 正则片段默认开启 `DOTALL`，`.` 可跨行。要限制在一行内用 `[^\n]+` 代替 `.+`。

## 一条规则匹配多段任务

一条龙日志里有 4 段任务（1/4、2/4、3/4、4/4），每段都以 `一条龙任务执行` 开头、`任务结束` 结尾。由于「同一时刻只允许一个窗口打开」，上面这一条规则会**自动**产出 4 个结果，每段任务各一个。

### 扩展提取表达式覆盖更多任务

不同任务段的关键信息不同。比如第 3 段包含「历练点」「探索派遣」「纪行」，我们想让提取表达式也能挑出这些字段，把它们加入新的行即可：

```
$((一条龙任务执行: \d+/\d+));$((邮件：[^\n]+));$((领取长效历练点奖励));$((探索派遣："完成"));$((纪行："无需领取"));$((任务结束))
```

- 第 1 段窗口 → 命中 `一条龙任务执行: 1/4`、`邮件："全部领取"`、`任务结束`
- 第 3 段窗口 → 命中 `一条龙任务执行: 3/4`、`领取长效历练点奖励`、`探索派遣："完成"`、`纪行："无需领取"`、`任务结束`
- 第 2、4 段窗口 → 只命中进度和结束标记（这些段没有匹配的字段，自动跳过）

这样**一条规则**就能复用到所有任务段。

> 如果不同任务段想分别推送、或字段差异很大，也可以**添加多条多行聚合规则**，每条规则各自维护窗口状态、各自产出结果。

## 常见技巧

### 用 `[^\n]+` 限制在一行内

提取表达式中的正则片段开启 `DOTALL`，`.` 会跨行。要匹配「这一行剩余内容」用 `[^\n]+`：

```
$((邮件：[^\n]+))    ✓ 只取邮件这一行
$((邮件：.+))        ✗ 会吞掉后面的所有行
```

### 用 `(?m)` 让 `^` `$` 匹配行首行尾

默认 `^` 只匹配整段窗口开头，`$` 只匹配结尾。加 `(?m)` 可让它们匹配每一行的首尾：

```
$((?m)^探索派遣：.+$)
```

### 精确匹配带引号的内容

日志里的 `"完成"`、`"无需领取"` 带引号。要精确匹配某一种状态，把引号也写进正则：

```
$((探索派遣："完成"))
```

这样只会挑出 `探索派遣："完成"`，跳过 `"全部领取"` 和 `"再次派遣"`。

### 转义特殊字符

如果起始/结束正则要匹配的字面文字含正则特殊字符（`. * + ? ( ) [ ] { } | ^ $ \`），记得加 `\` 转义。例如匹配 `"任务结束"` 里的引号通常无需转义，但匹配 `(1/4)` 要写 `\(1/4\)`。

> 注意：提取表达式中 `+`、`;`、`"` 在顶层是运算符。`$()` 内的所有内容都是正则，不需要担心冲突。如果要使用字面量文本，请用 `"..."` 包裹。

## 调试建议

1. 先只填**起始正则**和**结束正则**，**提取表达式留空**，用 🐛 调试按钮粘贴日志，确认窗口划分正确（每个窗口应包含一段完整任务）
2. 再填**提取表达式**，用 `$()` 包住要提取的部分，观察结果是否过滤掉了噪声行
3. 如果结果跨行贪吃，把 `.+` 换成 `[^\n]+`
4. 如果某段任务漏抓，检查提取表达式的正则片段是否覆盖了该段的关键字段
5. 调试弹窗里的「窗口 N」表示多行聚合产出的第 N 个窗口结果，与逐行模式不同
