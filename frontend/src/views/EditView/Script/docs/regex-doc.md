# 正则指南

正则表达式（简称「正则」）是一种**描述文本模式**的工具，你可以把它想象成「高级的搜索功能」：

- 普通搜索：搜索 `任务完成`，只能找到完全包含这几个字的行
- 正则搜索：搜索 `任务.{2}`，可以找到 `任务完成`、`任务失败`、`任务结束` 等任意「任务」后跟两个字的行

在 AutoMas 中，正则承担两种职责：

- **匹配**：过滤出需要处理的行（只判断「要不要处理」，不提取内容）
- **提取**：从文本中取出你想要的部分（用捕获组 `()` 标记要提取的内容）

> 下方分别讲解「匹配正则」与「提取正则」的用法，再给出完整的正则语法速查。

---

## 匹配正则

匹配正则的作用是**过滤**：只要行中能找到符合模式的文本，就算命中，该行才会被处理。

匹配正则用于以下字段：

- 正则模式的「匹配正则」字段（**必填，留空则该规则不生效**）
- 多行聚合模式的「起始正则 / 结束正则」字段（起始正则必填）

> 匹配正则采用 `search` 语义：在行中任意位置查找，找到即命中，不要求整行完全匹配。默认不开启任何标志（`.` 不匹配换行、`^`/`$` 匹配整段首尾），可用 `(?i)`/`(?m)`/`(?s)` 等内联标志覆盖。

以绝区零一条龙日志为例：

```
[23:48:19.773] [operation.py 675] [INFO]: 指令[ 咖啡店 ] 执行成功 返回状态 无需运行
[23:48:05.363] [operation.py 677] [ERROR]: 指令[ 等待大世界画面 ] 执行失败 返回状态 未到达大世界
[23:48:24.715] [operation.py 675] [INFO]: 指令[ 体力刷本 ] 执行成功 返回状态 剩余电量 187
```

期望效果：只处理「执行成功」的行，跳过「执行失败」。

那么匹配正则就可以写作：

```
指令\[.+?\] 执行成功
```

各行的命中情况：

| 日志行                                  | 是否命中 | 原因                                 |
| --------------------------------------- | -------- | ------------------------------------ |
| `...指令[ 咖啡店 ] 执行成功...`         | ✓        | 行中包含 `指令[ 咖啡店 ] 执行成功`   |
| `...指令[ 等待大世界画面 ] 执行失败...` | ✗        | 是「执行失败」，不包含「执行成功」   |
| `...指令[ 体力刷本 ] 执行成功...`       | ✓        | 行中包含 `指令[ 体力刷本 ] 执行成功` |

其中 `\[` 和 `\]` 是转义后的方括号（方括号在正则里有特殊含义，匹配字面方括号要加 `\`），`.+?` 表示「尽量短地匹配一段文字」。

## 提取正则

提取正则的作用是**提取**：从命中的文本里取出你要的内容。核心是用**捕获组 `()`** 标记想提取的部分。

提取正则写在「提取表达式」字段的 `$()` 内部（提取表达式的完整语法——函数链、拼接等——请参考「表达式指南」）。

> `$()` 内的正则默认开启 `DOTALL` 模式，`.` 可以匹配换行。如果只想匹配一行内的内容，用 `[^\n]+` 代替 `.+`。**只有捕获组 `()` 里的内容才会被提取**，无捕获组返回空串。

同样以上面的日志为例，期望提取指令名称：

```
咖啡店
体力刷本
```

提取表达式可以写作：

```
$(指令\[\s*(.+?)\s*\] 执行成功)
```

各步的处理效果（以第一条日志为例）：

| 步骤                           | 处理结果                                                                    |
| ------------------------------ | --------------------------------------------------------------------------- |
| `指令\[\s*(.+?)\s*\] 执行成功` | 匹配到 `指令[ 咖啡店 ] 执行成功`，捕获组提取 `咖啡店`，(即正则中()内的内容) |
| `$(...)`                       | 用于获取捕获组内容 `咖啡店`                                                 |

其中 `(.+?)` 是捕获组，括号里的内容会被提取出来；`\s*` 用来吃掉指令名两侧的空格，兼容 `咖啡店` 和 `咖啡店` 两种写法。

> 想提取**整段匹配**时，把整个正则包进一层括号即可，如 `$((指令\[\s*.+?\s*\] 执行成功))`。
> 提取表达式留空时，返回命中的整行原文。

## 正则语法

匹配正则和提取正则使用**同一套语法**，区别只在于：匹配正则只看是否命中，提取正则额外用捕获组 `()` 决定提取什么。

### 直接写文字

最简单的正则就是直接写你要找的文字：

```
任务完成
```

这会匹配所有包含「任务完成」四个字的行。

### 或-\|

竖线 `|` 表示「或者」，可以同时匹配多个关键词：

```
任务完成|任务失败|任务结束
```

匹配含有「任务完成」**或**「任务失败」**或**「任务结束」的行。

> 匹配关键字字段中的 `|` 也是「或」的语义。在 `$()` 内部，`|` 同样是正则的「或」；表达式的换行运算符是 `;`（不是 `|`），两者不会冲突。

### 字符

| 符号 | 含义                   | 举例       | 匹配结果               |
| ---- | ---------------------- | ---------- | ---------------------- |
| `.`  | 任意一个字符（除换行） | `任.完成`  | `任务完成`、`任意完成` |
| `\d` | 任意一个数字           | `第\d次`   | `第3次`、`第8次`       |
| `\D` | 任意一个非数字         | `\D+`      | `abc`、`任务`          |
| `\w` | 字母、数字或下划线     | `\w+`      | `hello`、`v3`          |
| `\W` | 非单词字符             | `\W+`      | 标点、空格             |
| `\s` | 空格、制表符等空白     | `\s+`      | 连续空格               |
| `\S` | 非空白字符             | `\S+`      | 一段不含空格的文字     |
| `\b` | 单词边界               | `\bINFO\b` | 独立的 `INFO` 单词     |
| `\B` | 非单词边界             | `\BINFO`   | `xINFO` 中的 `INFO`    |
| `\n` | 换行符                 | `.\n`      | 行尾换行               |
| `\t` | 制表符                 | `\t`       | 一个 Tab               |

> 记住一个规律：**小写字母匹配某类字符，对应大写字母是反义**（`\d`↔`\D`、`\w`↔`\W`、`\s`↔`\S`）。

### 字符类-\[\]

方括号 `[...]` 表示「匹配其中任意一个字符」：

| 写法       | 含义                 | 举例                    |
| ---------- | -------------------- | ----------------------- |
| `[abc]`    | a 或 b 或 c          | `[男女]` → `男` 或 `女` |
| `[0-9]`    | 0 到 9 任意数字      | 等同于 `\d`             |
| `[a-z]`    | a 到 z 任意小写字母  |                         |
| `[a-zA-Z]` | 任意字母（大小写）   |                         |
| `[^abc]`   | **非** a、b、c       | `[^0-9]` → 非数字       |
| `[^"]+`    | 一个或多个非引号字符 | 提取引号内的内容        |

> `^` 在方括号**里面**第一个位置表示「非」，在方括号**外面**表示「行首」。

### 次数

| 符号    | 含义        | 举例      | 匹配结果            |
| ------- | ----------- | --------- | ------------------- |
| `*`     | 0 次或多次  | `ab*`     | `a`、`ab`、`abbb`   |
| `+`     | 1 次或多次  | `\d+`     | `3`、`123`、`88`    |
| `?`     | 0 次或 1 次 | `colou?r` | `color`、`colour`   |
| `{n}`   | 恰好 n 次   | `\d{4}`   | `2026`              |
| `{n,}`  | 至少 n 次   | `\d{2,}`  | `12`、`123`、`1234` |
| `{n,m}` | n 到 m 次   | `\d{1,3}` | `5`、`42`、`999`    |

**贪婪与非贪婪**：`*`、`+`、`?`、`{n,m}` 默认是「贪婪」的，会尽可能多匹配。在后面加 `?` 变成「非贪婪」（尽量少匹配）：

| 写法  | 含义         | 举例          | 匹配结果                                              |
| ----- | ------------ | ------------- | ----------------------------------------------------- |
| `.+`  | 尽可能多匹配 | `指令\[.+\]`  | `指令[ A ] 执行成功 返回 [ B ]`（一直吃到最后的 `]`） |
| `.+?` | 尽可能少匹配 | `指令\[.+?\]` | `指令[ A ]`（吃到第一个 `]` 就停）                    |

> 提取结果「多了」或「少了」时，多半是贪婪问题，试试把 `+`/`*` 换成 `+?`/`*?`。

### 位置

| 符号 | 含义     | 举例       | 说明                           |
| ---- | -------- | ---------- | ------------------------------ |
| `^`  | 文本开头 | `^任务`    | 整段以「任务」开头             |
| `$`  | 文本结尾 | `完成$`    | 整段以「完成」结尾             |
| `\b` | 单词边界 | `\bINFO\b` | 独立的 `INFO`，不匹配 `xINFOx` |
| `\B` | 非边界   | `\Bend`    | `weekend` 中的 `end`           |

> 默认 `^`/`$` 只匹配整段文本的首尾。加 `(?m)` 可让它们匹配每一行的首尾。

### 分组

| 写法            | 含义                   | 举例                | 说明                               |
| --------------- | ---------------------- | ------------------- | ---------------------------------- |
| `(...)`         | 捕获组：提取这部分内容 | `(\d+) 次`          | 从 `运行 3 次` 提取 `3`            |
| `(?:...)`       | 非捕获组：只分组不提取 | `(?:完成\|失败)`    | 用「或」但不产生提取               |
| `(?P<名字>...)` | 命名捕获组             | `(?P<ver>\d+\.\d+)` | 给捕获组起名，多个命名组会一起返回 |

> 在提取表达式中，**只有捕获组 `()` 的内容会被提取**，非捕获组 `(?:...)` 不会。多个捕获组按顺序依次提取并用换行拼接。

### 环视（预查）

环视用来「往旁边看一眼」做条件判断，本身**不消耗文本**。`!` 代表「非」（否定断言）：

| 写法       | 名称     | 含义               | 举例                     | 说明                                 |
| ---------- | -------- | ------------------ | ------------------------ | ------------------------------------ |
| `(?=...)`  | 肯定先行 | 后面**要**跟着 ... | `指令\[(?=\s*执行).+?\]` | 指令名（去空格后）紧跟「执行」才命中 |
| `(?!...)`  | 否定先行 | 后面**不**跟着 ... | `指令\[(?!\s*通知).+?\]` | 指令名（去空格后）不是「通知」才命中 |
| `(?<=...)` | 肯定后行 | 前面**是** ...     | `(?<=版本:\s)\S+`        | 提取「版本: 」后面的内容             |
| `(?<!...)` | 否定后行 | 前面**不是** ...   | `(?<!\d)\d{2}`           | 前面不是数字的两位数                 |

**示例：只采集非「通知」类的指令**

```
匹配正则：指令\[(?!\s*通知).+?\] 执行成功
```

| 日志行                    | 是否命中 | 原因                                         |
| ------------------------- | -------- | -------------------------------------------- |
| `指令[ 咖啡店 ] 执行成功` | ✓        | `[` 后不是「空格+通知」，`(?!\s*通知)` 放行  |
| `指令[ 通知 ] 执行成功`   | ✗        | `[` 后是「空格+通知」，被 `(?!\s*通知)` 排除 |

> 环视非常适合「排除某些情况」（比如你不需要的节点日志）或「限定上下文」：用 `(?!...)` 排除，用 `(?<=...)` 限定前面。
> 注意：要把「可选空格」放进环视内部，写成 `(?!\s*通知)`，而不是 `\s*(?!通知)`——后者会因为 `\s*` 回溯到 0 而失效。

### 标志

标志可以改变正则的行为，写在正则最前面即可生效：

| 写法   | 含义       | 举例                 | 说明                               |
| ------ | ---------- | -------------------- | ---------------------------------- |
| `(?i)` | 忽略大小写 | `(?i)wrn\|warn`      | 同时匹配 `WRN`、`wrn`、`Warn`      |
| `(?m)` | 多行模式   | `(?m)^探索派遣：.+$` | `^`/`$` 匹配每行首尾               |
| `(?s)` | 单行模式   | `(?s).+`             | `.` 匹配换行（DOTALL）             |
| `(?x)` | 忽略空白   | `(?x)\d + \. \d+`    | 忽略正则中的空白，便于书写复杂正则 |

> 各字段默认标志：匹配正则字段默认无标志；提取表达式 `$()` 内默认已开启 `(?s)`（DOTALL）。如需其它标志自行追加即可。

### 转义特殊字符

如果匹配的文字里有正则特殊字符（`. * + ? ( ) [ ] { } | ^ $ \`），需要加 `\` 转义：

| 要匹配   | 正则写法   | 说明        |
| -------- | ---------- | ----------- |
| `3.14`   | `3\.14`    | `.` 要转义  |
| `[INFO]` | `\[INFO\]` | `[]` 要转义 |
| `(1/4)`  | `\(1/4\)`  | `()` 要转义 |
| `a+b`    | `a\+b`     | `+` 要转义  |

## 提取示例

### 示例 1：提取完成节点信息

**日志行**（绝区零一条龙）：

```
[23:48:47.265] [operation.py 675] [INFO]: 指令[ 丽都城募 ] 执行成功 返回状态 大世界-普通
[23:48:58.475] [operation.py 675] [INFO]: 指令[ 丽都周纪 (领奖励) ] 执行成功 返回状态 大世界-普通
[23:49:20.635] [operation.py 675] [INFO]: 指令[ 情报板 ] 执行成功 返回状态 大世界-普通
```

期望效果：

```
✓ 丽都城募
✓ 丽都周纪 (领奖励)
✓ 情报板
```

| 字段       | 值                                     |
| ---------- | -------------------------------------- |
| 匹配正则   | `指令\[.+?\] 执行成功`                 |
| 提取表达式 | `"✓ "+$(指令\[\s*(.+?)\s*\] 执行成功)` |

正则含义解释：

- **匹配正则** `指令\[.+?\] 执行成功`：`\[`、`\]` 匹配字面方括号，`.+?` 非贪婪匹配指令名，只命中「执行成功」的行
- **提取表达式**：`"✓ "` 字面前缀 + `$()` 提取指令名；`\s*` 吃掉指令名两侧空格，兼容 `丽都周纪 (领奖励)` 这种含空格和括号的名称

### 示例 2：BetterGI提取刷本信息

**日志行**（BetterGI）：

```
[07:04:45.062] [WRN] BetterGenshinImpact.GameTask.Common.TaskControl
自动秘境："存在角色死亡，复活后重试秘境..."

[07:04:47.074] [INF] BetterGenshinImpact.GameTask.Common.TaskControl
自动秘境：传送到秘境"山风的荆冕"
```

期望效果：`自动秘境：山风的荆冕`

| 字段       | 值                                    |
| ---------- | ------------------------------------- |
| 匹配正则   | `自动秘境：传送到`                    |
| 提取表达式 | `"自动秘境："+$(传送到秘境"([^"]+)")` |

正则含义解释：

- **匹配正则** `自动秘境：传送到`：只命中「传送到秘境」的行，跳过「角色死亡」那一行
- **提取表达式**：`"自动秘境："` 字面前缀 + `$()` 提取引号内的副本名；`[^"]+` 匹配到下一个引号为止
- `$()` 内的 `"` 是正则的字面引号字符，不会被当作字面量分隔符

**日志行**（ok-ef）：

```
2026-08-04 22:03:16.377  INFO            main ThreadId(01) pyappify_lib::utils::window: send_notification: 升级成功: ok-ef v1.0.14
```

期望效果：`升级成功ok-ef v1.0.14`

| 字段       | 值                               |
| ---------- | -------------------------------- |
| 匹配正则   | `升级成功`                       |
| 提取表达式 | `"升级成功"+$(升级成功:\s*(.+))` |

正则含义解释：

- **匹配正则** `升级成功`：命中含「升级成功」的行
- **提取表达式**：`"升级成功"` 字面前缀 + `$()` 提取冒号后的版本号；`(.+)` 匹配行内剩余内容
- 拼接后 `升级成功` + `ok-ef v1.0.14` = `升级成功ok-ef v1.0.14`，恰好去掉了原来的 `: `

### 示例 4：排除不必要的节点

**日志行**（绝区零一条龙）：

```
[23:49:20.635] [operation.py 675] [INFO]: 指令[ 情报板 ] 执行成功 返回状态 大世界-普通
[23:49:43.677] [operation.py 675] [INFO]: 指令[ 随便观 自动托管 ] 执行成功 返回状态 成功
[23:49:46.388] [operation.py 675] [INFO]: 指令[ 随便观 ] 执行成功 返回状态 大世界-普通
[23:49:52.855] [operation.py 675] [INFO]: 指令[ 通知 ] 执行成功 返回状态 成功
[23:49:52.914] [operation.py 675] [INFO]: 指令[ 一条龙 ] 执行成功 返回状态 全部结束
```

期望效果：采集除 通知 、一条龙以及随便观 自动托管 外的成功指令

| 字段       | 值                                                             |
| ---------- | -------------------------------------------------------------- |
| 匹配正则   | `指令\[(?!\s*(?:通知\|一条龙\|随便观 自动托管)).+?\] 执行成功` |
| 提取表达式 | `"✓ "+$(指令\[\s*(.+?)\s*\] 执行成功)`                         |

正则含义解释：

- **匹配正则** 用否定先行 `(?!\s*(?:通知|一条龙|随便观 自动托管))` 一次性排除三个指令名
- `\s*` 放在环视**内部**，先吃掉 `[` 后的空格再判断，避免 `\s*` 回溯到 0 而失效（详见「环视」章节的注意）
- `随便观 自动托管` 作为整体排除项，单独的 `随便观` 不受影响（仍会被采集）
- **提取表达式** 加 `✓ ` 前缀并提取指令名

### 示例 5：格式化列表

**日志行**（ok-ef）：

```
2026-08-14 15:51:37,614 INFO TaskExecutor DailyTask:任务失败标记 | ⭐送礼: 异常:
2026-08-14 15:51:37,614 INFO TaskExecutor DailyTask:info_set 未处理的任务列表 ['买信用商店', '刷体力', '活动奖励', '日常奖励', '演算', '传送到帝江号右侧传送点', '执行外部命令']
2026-08-14 15:51:37,615 INFO TaskExecutor DailyTask:info_set 当前失败的任务 送礼
2026-08-14 15:51:43,616 INFO TaskExecutor DailyTask:发生异常，继续游戏
```

期望效果：

```
⏸买信用商店
⏸刷体力
⏸活动奖励
⏸日常奖励
⏸演算
❌送礼
```

这是一个相对复杂的处理逻辑，需要配两条规则：一条提取未处理任务列表，一条提取当前失败的任务。

**配置一：未处理任务列表**

| 字段       | 值                 |
| ---------- | ------------------ | --------------------------------- | -------------------------- | ------------------------- |
| 匹配正则   | `未处理的任务列表` |
| 提取表达式 | `"⏸"+$((?:\[       | , )'((?!(?:传送到帝江号右侧传送点 | 执行外部命令)')[^']+)'(?=, | \])).replace("\n","\n⏸")` |

正则含义解释：

- **匹配正则** `未处理的任务列表`：命中任务列表那一行
- **提取表达式** 用 `'([^']+)'` 匹配列表里每个带引号的任务名，`$()` 会把多个匹配逐行输出
- `(?:\[|, )` 锚定引号前必须是 `[` 或 `, `（列表分隔符），避免被排除项的**闭合引号**误当作下一个项的开头
- `(?!(?:传送到帝江号右侧传送点|执行外部命令)')` 否定先行排除两个非任务项；末尾 `(?=,|\])` 确保引号后是分隔符或 `]`
- `.replace("\n","\n⏸")` 给第 2 行及之后每行加 `⏸` 前缀；开头再补一个 `"⏸"` 给第 1 行，实现逐行前缀（`\n` 在字面量中解释为真实换行）

**配置二：当前失败的任务**

| 字段       | 值                               |
| ---------- | -------------------------------- |
| 匹配正则   | `当前失败的任务`                 |
| 提取表达式 | `"❌"+$(当前失败的任务\s+(\S+))` |

正则含义解释：

- **匹配正则** `当前失败的任务`：命中失败任务那一行
- **提取表达式**：`"❌"` 字面前缀 + `$()` 提取任务名；`\S+` 匹配一个非空白单词
- 输出 `❌送礼`

- 提取所有成功节点

- 过滤成功节点中不需要的节点（黑白名单均可）

- 提取所有失败节点

这里我们写三个推送配置来实现

1. 匹配成功节点并过滤掉不需要的节点
2. 匹配失败节点保留返回状态
3. 对于体力刷本这个节点单独配置

如下：

配置一（成功节点，过滤导航类指令与体力刷本）：

| 字段       | 值                                                                              |
| ---------- | ------------------------------------------------------------------------------- |
| 匹配正则   | `指令\[(?!\s*(?:等待大世界画面\|返回大世界\|前往菜单\|体力刷本)).+?\] 执行成功` |
| 提取表达式 | `"✓ "+$(指令\[\s*(.+?)\s*\] 执行成功)`                                          |

- 否定先行排除 `等待大世界画面`、`返回大世界`、`前往菜单` 这类导航/过渡节点，以及交给配置三处理的 `体力刷本`
- 排除 `体力刷本` 是为了避免和配置三重复采集

配置二（失败节点，过滤进入游戏，保留返回状态）：

| 字段       | 值                                                            |
| ---------- | ------------------------------------------------------------- |
| 匹配正则   | `指令\[(?!\s*进入游戏).+?\] 执行失败`                         |
| 提取表达式 | `"✗ "+$(指令\[\s*(.+?)\s*\] 执行失败)+" "+$(返回状态\s+(.+))` |

- 用两个 `$()` 分别提取指令名和返回状态，中间用 `" "` 字面空格拼接成同一行
- `进入游戏` 的失败属于前置环境问题，排除以免干扰

配置三（体力刷本，单独提取剩余电量）：

| 字段       | 值                                           |
| ---------- | -------------------------------------------- |
| 匹配正则   | `体力刷本.+执行成功`                         |
| 提取表达式 | `"✓ 体力刷本 剩余电量 "+$(剩余电量\s+(\d+))` |

- 匹配正则用 `体力刷本.+执行成功` 只命中「执行成功」那一行，跳过同名的「节点」行
- 提取表达式把指令名写死为字面量，只动态提取 `剩余电量` 后的数字
