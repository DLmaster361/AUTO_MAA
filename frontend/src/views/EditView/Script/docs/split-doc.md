# 字符串切割指南

字符串切割就是**按关键字过滤行，再掐头去尾提取中间内容**。你可以把它想象成剪刀：

1. 先用关键字**筛选**出你要的行（匹配关键字）
2. 再用关键字**剪掉**行首不需要的部分（掐头关键字）
3. 最后用关键字**剪掉**行尾不需要的部分（去尾关键字）

> 如果你了解正则或函数，字符串切割能做的事它们都能做。字符串切割胜在简单直观，不需要记任何语法，适合格式固定的日志。

---

## 从一个例子开始

以绝区零一条龙日志为例：

```
[17:13:13.678] [operation.py 675] [INFO]: 指令[ 邮件 ] 执行成功 返回状态 大世界-普通
[17:14:00.922] [operation.py 675] [INFO]: 指令[ 录像店营业 ] 执行成功 返回状态 大世界-普通
[17:13:13.680] [operation.py 429] [INFO]: 指令[ 执行应用组 one_dragon ] 节点 执行应用 返回状态 下一个
```

期望效果：只保留执行成功的指令部分：

```
指令[ 邮件 ] 执行成功
指令[ 录像店营业 ] 执行成功
```

我的配置可以写作：

| 输入框     | 值                                                   |
| ---------- | ---------------------------------------------------- |
| 匹配关键字 | `指令[ 邮件 ] 执行成功\|指令[ 录像店营业 ] 执行成功` |
| 掐头关键字 | `[INFO]: `                                           |
| 去尾关键字 | ` 返回状态`                                          |

各步处理效果（以第一条日志为例）：

| 步骤                       | 处理结果                                                                               |
| -------------------------- | -------------------------------------------------------------------------------------- |
| 匹配关键字命中             | `[17:13:13.678] [operation.py 675] [INFO]: 指令[ 邮件 ] 执行成功 返回状态 大世界-普通` |
| 掐头 `[INFO]: `（含包含）  | `指令[ 邮件 ] 执行成功 返回状态 大世界-普通`                                           |
| 去尾 ` 返回状态`（含包含） | `指令[ 邮件 ] 执行成功`                                                                |
| 第三条日志                 | 匹配关键字未命中（是「节点 执行应用」），整行跳过                                      |

这样就可以获得一段干净的进程日志用于推送了。

---

## 三个输入框

| 输入框     | 作用                                         | 留空含义                 |
| ---------- | -------------------------------------------- | ------------------------ |
| 匹配关键字 | 过滤命中的行，只有包含该关键字的行才会被处理 | **该规则不生效**（必填） |
| 掐头关键字 | 从行首截取到关键字处，去掉前面的内容         | 不掐头                   |
| 去尾关键字 | 从关键字处截取到行尾，去掉后面的内容         | 不去尾                   |

> 匹配关键字是必填项，留空时整条规则不会生效，避免误开启后匹配所有行造成海量推送。

---

## 「包含」复选框

掐头关键字和去尾关键字旁边各有一个「包含」复选框，控制关键字本身的去留：

- **勾选「包含」** → 连同关键字一起去掉
- **不勾选「包含」** → 保留关键字

以日志 `[INFO]: 指令[ 邮件 ] 执行成功 返回状态 大世界-普通` 为例：

| 操作                      | 结果                                                 |
| ------------------------- | ---------------------------------------------------- |
| 掐头 `[INFO]: ` 不勾包含  | `[INFO]: 指令[ 邮件 ] 执行成功 返回状态 大世界-普通` |
| 掐头 `[INFO]: ` 勾选包含  | `指令[ 邮件 ] 执行成功 返回状态 大世界-普通`         |
| 去尾 ` 返回状态` 不勾包含 | `指令[ 邮件 ] 执行成功 返回状态`                     |
| 去尾 ` 返回状态` 勾选包含 | `指令[ 邮件 ] 执行成功`                              |

> 「包含」控制的是**关键字本身**是否保留，不影响关键字之前/之后的内容。

---

## 多关键字匹配

匹配关键字支持用 `|` 分隔多个关键字，**任一命中即通过**。

绝区零一条龙日志里有多个流程节点，结构相同仅关键字不同，就可以用 `|` 复用同一套逻辑：

```
[17:13:13.678] [operation.py 675] [INFO]: 指令[ 邮件 ] 执行成功 返回状态 大世界-普通
[17:14:00.922] [operation.py 675] [INFO]: 指令[ 录像店营业 ] 执行成功 返回状态 大世界-普通
[17:14:27.373] [operation.py 675] [INFO]: 指令[ 咖啡店 ] 执行成功 返回状态 无需运行
```

| 输入框     | 值                                                                            |
| ---------- | ----------------------------------------------------------------------------- |
| 匹配关键字 | `指令[ 邮件 ] 执行成功\|指令[ 录像店营业 ] 执行成功\|指令[ 咖啡店 ] 执行成功` |
| 掐头关键字 | `[INFO]: `（勾选包含）                                                        |
| 去尾关键字 | ` 返回状态`（勾选包含）                                                       |

期望效果：

```
指令[ 邮件 ] 执行成功
指令[ 录像店营业 ] 执行成功
指令[ 咖啡店 ] 执行成功
```

这样就可以仅通过一个配置完成一条龙的所有流程节点提取。

> 这里的 `|` 是字符串切割字段专用的「或」分隔符，与正则中的 `|` 语义一致但写在不同字段。

## 常见技巧

### 关键字位置不固定

掐头和去尾关键字使用**子串查找**（`find`），只要行中包含该关键字就会截取，不要求在行首或行尾。如果需要更精确的位置控制，请使用「正则」模式。

### 空格处理

提取结果会自动去掉首尾空格（`strip`）。如果关键字后面有空格，把空格也写进关键字可以更精确地截取：

```
掐头关键字: 当前版本:     ← 包含冒号和空格，截掉后直接是版本号
掐头关键字: 当前版本      ← 不含空格，截掉后结果前面可能有空格
```

### 只过滤不切割

如果只需要过滤出某些行，不需要掐头去尾，只填「匹配关键字」即可，掐头和去尾留空。提取结果就是整行原文。

---

## 调试建议

1. 先只填**匹配关键字**，掐头去尾留空，用 🐛 调试按钮粘贴日志，确认能过滤出正确的行
2. 再填**掐头关键字**，观察是否正确截掉了行首内容
3. 最后填**去尾关键字**，观察是否正确截掉了行尾内容
4. 如果关键字没生效，检查日志中是否真的包含该关键字（注意空格、全角/半角字符）
5. 调试弹窗会显示每行是否命中（✓/✗）以及提取结果
